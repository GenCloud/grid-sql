# Возможности

Что Grid умеет сегодня: SQL, хранение, транзакции, поведение кластера и инструменты.

## Границы применимости

| Область | В продукте |
|---------|------------|
| SQL + TX + горячая RAM + диск | Да — один стек |
| Клиенты | `grid://` (реактивный) и `jdbc:grid://` (JDBC) |
| Кластер | ORCHID, доставка OpLog пирам, смена writer, режимы multi-site |
| Чужой SQL-протокол / общий NFS `dataDir` / два писателя | Нет |

## SQL

- Запросы разбираются грамматикой ANTLR: Simplified SQL, ограниченный диалект — не полная копия «большого» SQL.
- DDL для таблиц, индексов и ограничений.
- DML: `INSERT`, `UPDATE`, `DELETE`, `TRUNCATE TABLE`, `UPSERT`, `INSERT … ON CONFLICT` и подмножество `MERGE`.
- SELECT: фильтры, соединения INNER / LEFT / RIGHT / FULL JOIN, `GROUP BY` и `PARTITION BY` по нескольким колонкам, `ORDER BY`, `LIMIT`, `OFFSET`.
- `EXISTS` / `NOT EXISTS`, обобщённые табличные выражения (`WITH`), представления, оконные функции, скалярные и табличные пользовательские функции — в пределах диалекта.
- `PREPARE` и параметры запросов.
- `EXPLAIN`, а для тяжёлых планов — адаптивное исполнение (AQE).
- Строки хранятся как двоичные записи с доступом к отдельным полям; Java-класс предметной области необязателен.

См. [основы SQL](../sql/fundamentals.md), [DDL](../sql/ddl.md), [DML](../sql/dml.md), [матрицу поддержки SQL](../sql/support-matrix.md).

## Хранение

- Данные шардируются в памяти; индексы обновляются через очередь.
- На диске: запечатанные файлы карты (GMAP) и журнал изменений (OpLog).
- При старте узел либо загружает всё в память (`FULL`), либо отображает файлы и подтягивает ключи по обращению (`LAZY`).
- Ограничение рабочего набора вытесняет холодные ключи и перечитывает их с диска при промахе.
- Индексы B+ по одной или нескольким колонкам; битовые индексы — только явным `CREATE BITMAP INDEX`.
- Вторичные индексы тоже могут быть запечатаны, поэтому промах по индексу не превращается в полный обход раздела.
- Локальное долговременное хранение и репликация на соседние узлы — независимые переключатели: один узел может хранить данные надёжно и без реплик.

См. [хранение](../understand/storage-sealed-gmap.md), [долговременное хранение](../configure-and-operate/configuration/durability.md).

## Транзакции

- Одно TCP-соединение несёт несколько независимых транзакций.
- До COMMIT изменения видны только внутри своей транзакции.
- Блокировки по ключу записи; `FOR UPDATE` / `SKIP LOCKED` на пишущем (и на пирах, когда Dist FOR UPDATE включён — из `peers` репликации, не из `distributed-peers`). Подробнее: [чтение с реплики](../configure-and-operate/operations/replica-reads.md).
- DDL внутри открытой транзакции отклоняется.

## Права доступа (RBAC)

- `CREATE USER` / `DROP USER` / `ALTER USER … PASSWORD`, `CREATE ROLE` / `DROP ROLE`, `GRANT` / `REVOKE` и `GRANT ROLE … TO user` — всё хранится в `privileges.meta` (локальный файл на узел; репликация его не доставляет — применяйте на каждом SQL-узле, куда ходят приложения). См. [безопасность](../configure-and-operate/operations/security.md).
- Пустой каталог пользователей означает вход без пароля, а первый созданный пользователь становится администратором.
- Когда пользователи уже есть, AUTH в кадре обязателен, а права на таблицы проверяются, в том числе с обеих сторон JOIN.
- Отдельной команды `REVOKE ROLE` нет: членство в роли снимается через `DROP ROLE`.

См. [безопасность](../configure-and-operate/operations/security.md), [DDL](../sql/ddl.md).

## Кластер

- Перед фиксацией записи узлы согласуют фазу ORCHID и кворум digest.
- Журнал уходит на соседние узлы по TCP; реплики применяют его и устраняют расхождения.
- Доступны размещение реплик, перенос шардов и асинхронная либо синхронная доставка между площадками.
- Чтение с реплики выполняется по явной политике.
- При обрыве канала роль применения изменений может перейти на другой узел.
- Регионы закрепляются за узлами через `REGION_CLAIM`.

См. [ORCHID](../understand/orchid-consensus.md), [репликация](../configure-and-operate/configuration/replication.md).

## Клиенты и инструменты

- Реактивный доступ: `grid-sql-client`, URL `grid://`, `ConnectionFactory` и `TxContext`.
- JDBC: тот же артефакт, URL `jdbc:grid://`, драйвер `org.genfork.grid.jdbc.GridDriver` — стабильный синхронный аналог реактивного API для стеков на DataSource/DAO и для IDE.
- Консоль SQL, автоконфигурация Spring Boot и отдельный jar SQL-сервера.
- Сценарии Apache JMeter поверх `grid://`; через JDBC нагрузку не подают, так как синхронные вызовы искажают p95.
- Jepsen проверяет согласованность на одной площадке и между площадками; цифры ёмкости снимает нагрузочный стенд.

См. [подключение клиентов](connect-clients.md), [JDBC-клиент](../develop/jdbc-tooling.md).
