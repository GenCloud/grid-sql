# Глоссарий

Краткие определения терминов из эксплуатационных и архитектурных страниц. Имена API и ключей YAML (`writerEligible`, `peers:`) не переводятся — в таблице только смысл.

| Термин | Смысл |
|--------|-------|
| ORCHID | Согласование узлов: фазовая синхронизация (модель Ёсики Курамото) и кворум дайджестов |
| Параметр порядка `R` | Насколько согласованы фазы среди живых узлов, которые видит текущий узел (по умолчанию — своей площадки) |
| Кворум дайджестов | Согласие большинства на одном digest предложения до того, как коммит станет видимым |
| Выбор пишущего узла по фазе | Единственный активный writer среди синхронных узлов (`min(nodeId)` среди себя и увиденных) |
| OpLog | Журнал изменений, только на дозапись |
| Sealed GMAP | Запечатанные файлы карты на диске (`.gmap`); вместе с OpLog — долговечное хранилище |
| `.sbpt` / `.sbm` | Запечатанные вторичное B+-дерево и bitmap-индекс |
| Промах sealed | Промах рабочего набора: ключ подгружается из запечатанных файлов в RAM |
| Рабочий набор | `GridScalableMap` и индексы в памяти; при durability это ускоритель, а не единственный источник истины |
| Подгрузка (hydrate) | Загрузка запечатанных файлов и OpLog в рабочий набор при старте (`FULL` или `LAZY`) |
| PIN | Пометка, которая не даёт переносить шард ключа, пока жива (слой overlay) |
| Смена владельца шарда (cutover) | Передача шарда другому узлу, когда тот уже подтянул журнал (`CUTOVER_DONE`); см. [размещение](../understand/overlay-and-swarm.md) |
| `grid://` | SQL URL реактивного клиента |
| `jdbc:grid://` | SQL URL JDBC-клиента (тот же протокол) |
| `maxTxContexts` | Потолок логических сессий на одном TCP-соединении |
| `writerEligible` | Метаданные протокола: узел может принимать запись |
| `regionEpoch` | Счётчик эпохи активной площадки при изоляции площадок |
| AQE | Адаптивное исполнение тяжёлых SELECT: параллельный скан и `DIST_MAP` |
| ASYNC_SHIP / SYNC_VOTERS | Режимы доставки журнала между площадками: асинхронная отправка или синхронное подтверждение дайджестов |
| HomologousRepair | Подтягивание по locus и повторная отправка недостающих операций |
| AdaptiveReplicaSwarm | Подсказки размещения, которые могут перенести владение шардом |
| SqlCli | Интерактивная оболочка в `grid-sql-client` (синхронная граница `main`) |
| `PROMOTE_NOTIFY` | Кадр протокола: клиенту сообщают о смене пишущего узла |
| SparseCatchUp | Подтягивание отстающего узла диапазоном OpLog, без пересылки всего журнала |
| Идентификатор прогона | Имя конкретного прогона нагрузки или JMH в его JSON и в `SUMMARY.md` |
| Допуск записи | Условие ORCHID — фаза `R` и кворум дайджестов, — при котором коммит становится видимым |
| Пишущий узел (`proposer`) | Узел, который сейчас принимает запись; выбирается по фазе среди синхронных |
| Witness | Узел-свидетель на другой площадке: участвует в кворуме захвата роли, не обслуживает ни запись, ни чтение |
| Изоляция площадок | Режим `grid.replication.region.enabled`: роли Active / Hold / Witness и `regionEpoch` вместо фиксированной главной площадки |
| Подтягивание реплики | Когда отстающий узел догоняет журнал (SparseCatchUp, HomologousRepair), а не ставится с нуля |
| Готовность (readiness) | Проба Actuator: SQL слушает и, при включённой репликации, ORCHID синхронизирован; иначе трафик слать нельзя |

## Не путать

- **OpLog и sealed — разное.** Журнал — поток изменений, запечатанные файлы (`.gmap`, `.sbpt`) — снимок после уплотнения. Одни только запечатанные файлы свежие коммиты не восстановят.
- **Durability и репликация — разное.** `grid.durability.enabled` даёт локальные ORCHID, OpLog и запечатанные файлы и работает на одном узле. `grid.replication.enabled` добавляет пиров, кворум и подтягивание отстающих.
- **Рабочий набор — не источник истины.** При durability RAM работает ускорителем; истина — в журнале и запечатанных файлах.

Термина нет в таблице — смотрите страницу соответствующего раздела. Опорные цифры нагрузки: [ёмкость и пороги](../performance/capacity-slo.md).
