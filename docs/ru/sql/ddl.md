# DDL

DDL меняет каталог: `TableCatalog` и `TableSchema`. Разбор — ANTLR (`SimplifiedSql.g4`), исполнение — `SqlDdlExecutor`.

Одно правило запомнить сразу: **DDL внутри открытой транзакции отклоняется**. Сначала `COMMIT` или `ROLLBACK`, потом изменение схемы. Каталог не участвует в откате, поэтому в транзакционный буфер он не попадает.

Имена объектов пишутся без кавычек: латинские буквы, цифры и подчёркивание, регистр не важен, при необходимости с квалификатором `схема.объект`. Идентификаторов в двойных кавычках нет, поэтому назвать колонку ключевым словом не получится. Полный синтаксис — в [поддерживаемых конструкциях](support-matrix.md).

## CREATE TABLE

```sql
CREATE TABLE IF NOT EXISTS orders (
  id          BIGINT PRIMARY KEY,
  customer_id BIGINT NOT NULL,
  total       DOUBLE,
  status      VARCHAR,
  created_at  TIMESTAMPTZ
);
```

`IF NOT EXISTS` делает оператор повторяемым: если таблица уже есть, оператор проходит без ошибки и без изменений. Это удобно для скриптов инициализации, которые выполняются при каждом старте приложения.

Типы колонок — см. [типы](types.md).

### Первичный ключ

Первичный ключ обязателен по смыслу: по нему считается шард и делается точечный поиск. Объявить можно двумя способами.

```sql
-- на колонке
CREATE TABLE users (id BIGINT PRIMARY KEY, email VARCHAR);

-- составной, отдельным элементом таблицы
CREATE TABLE order_items (
  order_id BIGINT,
  line_no  INT,
  sku      VARCHAR,
  PRIMARY KEY (order_id, line_no)
);
```

Колонки первичного ключа участвуют в вычислении шарда. Запрос с равенством по полному ключу превращается в точечное чтение, а не в скан.

### Автоинкремент

Два способа, оба сводятся к генерации значения на сервере:

```sql
CREATE TABLE events (
  id   BIGSERIAL PRIMARY KEY,
  body VARCHAR
);

CREATE TABLE tickets (
  id   BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  note VARCHAR
);
```

`SERIAL` даёт `INT`, `BIGSERIAL` — `BIGINT`. `GENERATED BY DEFAULT AS IDENTITY` значит: если значение передали явно, берётся оно; если нет — генерируется следующее.

### NOT NULL

```sql
CREATE TABLE accounts (
  id      BIGINT PRIMARY KEY,
  owner   VARCHAR NOT NULL,
  balance DOUBLE
);
```

Колонка без `NOT NULL` допускает `NULL`. Вставка `NULL` в `NOT NULL` отклоняется.

## Ограничения

### FOREIGN KEY

```sql
CREATE TABLE order_lines (
  id       BIGINT PRIMARY KEY,
  order_id BIGINT NOT NULL,
  sku      VARCHAR,
  CONSTRAINT fk_order FOREIGN KEY (order_id) REFERENCES orders (id)
    ON DELETE CASCADE
    ON UPDATE RESTRICT
);
```

Ссылочная целостность проверяется при вставке и обновлении дочерней строки: родитель должен существовать. Действия на удаление и обновление родителя:

| Действие | Поведение |
|----------|-----------|
| `RESTRICT` | Операция над родителем отклоняется, пока есть дочерние строки |
| `CASCADE` | Дочерние строки удаляются или обновляются вслед за родителем |
| `SET NULL` | Ссылающиеся колонки дочерних строк обнуляются |

Имя ограничения через `CONSTRAINT` необязательно, но с ним понятнее читать ошибки.

### CHECK

```sql
CREATE TABLE payments (
  id     BIGINT PRIMARY KEY,
  amount DOUBLE,
  CONSTRAINT positive_amount CHECK (amount > 0)
);
```

Выражение `CHECK` — обычное булево выражение диалекта: сравнения, `AND`/`OR`/`NOT`, `BETWEEN`, `IN`, `IS NULL`. Проверяется на каждой мутации строки.

### Уникальность

Отдельного `UNIQUE` на колонке нет. Уникальность объявляется индексом:

```sql
CREATE UNIQUE INDEX uq_users_email ON users (email);
```

Подробности — [индексы](indexes.md).

## Индексы

```sql
CREATE INDEX idx_orders_customer ON orders (customer_id);
CREATE INDEX idx_orders_cust_status ON orders (customer_id, status);
CREATE BITMAP INDEX idx_orders_status ON orders (status);

DROP INDEX idx_orders_customer ON orders;
```

Одна колонка — B+ дерево указателей, несколько — составное дерево. `BITMAP` включается **только** явным `CREATE BITMAP INDEX` и только на одной колонке; через конфигурацию YAML его включить нельзя. Когда bitmap уместен и как индекс участвует в плане — [индексы](indexes.md).

## ALTER TABLE

```sql
ALTER TABLE orders ADD COLUMN channel VARCHAR;
ALTER TABLE orders ADD CONSTRAINT total_nonneg CHECK (total >= 0);
ALTER TABLE orders DROP COLUMN channel;
```

Добавленная колонка у существующих строк читается как `NULL` — переписывать данные не нужно. Смены типа колонки и переименования нет.

## DROP TABLE

```sql
DROP TABLE IF EXISTS orders;
```

Удаляет схему, данные и вторичные индексы таблицы.

## Схемы

```sql
CREATE SCHEMA IF NOT EXISTS analytics;
SET SCHEMA analytics;
DROP SCHEMA analytics RESTRICT;
```

Имя таблицы можно писать с квалификатором: `analytics.orders`. `DROP SCHEMA` требует `RESTRICT` — каскадного удаления схемы нет.

## Последовательности

```sql
CREATE SEQUENCE IF NOT EXISTS order_seq START WITH 1000 INCREMENT BY 1;

SELECT NEXTVAL('order_seq');
SELECT CURRVAL('order_seq');

UPSERT INTO orders (id, status) VALUES (NEXTVAL('order_seq'), 'new');

DROP SEQUENCE IF EXISTS order_seq;
```

Модификатор `RECLAIM` разрешает переиспользовать освободившиеся значения — полезно там, где важна плотность идентификаторов, а не строгая монотонность.

## Представления

```sql
CREATE VIEW active_orders AS
  SELECT id, customer_id, total FROM orders WHERE status = 'active';

CREATE MATERIALIZED VIEW daily_totals AS
  SELECT customer_id, SUM(total) FROM orders GROUP BY customer_id;

REFRESH MATERIALIZED VIEW daily_totals;

DROP VIEW IF EXISTS active_orders;
```

Обычное представление подставляется в запрос. Материализованное хранит результат и обновляется по команде `REFRESH`, автоматического обновления нет.

## Функции и триггеры

Функция привязывается к Java-классу и методу. Никакого выполнения строки с кодом:

```sql
CREATE FUNCTION normalize_email(value VARCHAR) RETURNS VARCHAR
  AS CLASS 'com.example.GridFunctions' METHOD 'normalizeEmail';

DROP FUNCTION IF EXISTS normalize_email;
```

Триггер описывает момент срабатывания и тело в виде SQL-строки, где доступны `OLD.col` и `NEW.col`:

```sql
CREATE TRIGGER audit_orders AFTER UPDATE ON orders
  FOR EACH ROW
  WHEN 'NEW.status != OLD.status'
  AS 'UPSERT INTO order_audit (id, status) VALUES (NEW.id, NEW.status)';

DROP TRIGGER IF EXISTS audit_orders ON orders;
```

## Пользователи и права

```sql
CREATE USER reporting PASSWORD 'secret';
ALTER USER reporting PASSWORD 'rotated';
GRANT SELECT ON SCHEMA analytics TO reporting;
REVOKE INSERT, UPDATE ON TABLE orders FROM reporting;
DROP USER reporting;

CREATE ROLE readers;
GRANT SELECT ON TABLE orders TO ROLE readers;
GRANT ROLE readers TO reporting;
DROP ROLE readers;
```

Набор привилегий: `SELECT`, `INSERT`, `UPDATE`, `DELETE`, `DDL`. Цель — схема или таблица. Роли хранят права; `GRANT ROLE … TO user` даёт членство (проверяется при проверке полномочий).

`REVOKE … FROM user` снимает права у пользователя. Отдельной команды `REVOKE ROLE` нет: чтобы убрать членство, удалите роль (`DROP ROLE`). Каталог на диске: `{grid.sql.data-dir}/catalog/privileges.meta`. Оператору: [безопасность](../configure-and-operate/operations/security.md).

## Что отклоняется

| Форма | Почему |
|-------|--------|
| Любой DDL внутри открытой транзакции | Схема меняется вне транзакционного буфера |
| Тип `JSONB` | Используйте `JSON` или `VARCHAR` — это непрозрачный текст UTF-8 |
| Незнакомый токен типа | Список допустимых — в [типах](types.md) |
| `ALTER TABLE ... ALTER COLUMN TYPE`, переименование | Не поддерживается: пересоздайте таблицу |
| `DEFAULT <выражение>` у колонки | Значения по умолчанию задаёт приложение или `IDENTITY`/`SERIAL` |
| `CREATE BITMAP INDEX` по нескольким колонкам | Bitmap — только одна колонка |
| `DROP SCHEMA` без `RESTRICT` | Каскадного удаления схемы нет |
| Частичные индексы, индексы по выражению | Индексируются только колонки |
| `ALTER TABLE … DROP CONSTRAINT` | Ограничение снимается пересозданием таблицы |
| Идентификатор в двойных кавычках | Имена — только слова без кавычек |

Ошибка разбора или проверки каталога означает, что оператор не применился вовсе. Частично применённого DDL не бывает.

## Смена схемы и клиенты

Каждое изменение схемы поднимает счётчик версии схемы (`ServerMeta.schemaEpoch`). Клиенты видят новый счётчик и перечитывают метаданные колонок. Специально переподключаться не нужно.
