# EXPLAIN и адаптивное исполнение (AQE)

Текст EXPLAIN строит только `SqlExplainService`. Тяжёлые SELECT могут идти через Adaptive Query Execution (AQE) и параллельный map по локальным шардам.

Оператору: смотрите метки в EXPLAIN, чтобы понять, **почему** запрос тяжёлый и не «сломался ли план». Корректность строк не зависит от AQE — меняется способ разбиения работы на узле.

Опорные цифры и пороги: [сводные результаты](../performance/results.md), [ёмкость](../performance/capacity-slo.md).

## EXPLAIN

```sql
EXPLAIN SELECT * FROM t WHERE name = 'x';
```

| Вид | Смысл |
|-----|-------|
| `AQE_PARALLEL` | Запрос допущен к параллельному скану кусками на этом узле |
| `DIST_MAP` | Запрос допущен к map по срезам локальных шардов |

Планировщик не делает dry-run физического EXPLAIN ради оценки тяжести: `EXPLAIN` показывает выбранный путь, а не «сколько бы стоило при другом плане».

### Как читать ответ

1. Есть `AQE_PARALLEL` / `DIST_MAP` — оценка допуска сочла запрос тяжёлым и выбрала параллельный путь.
2. Нет этих меток — обычный (локальный) путь: индекс или скан без AQE.
3. Корректность результата не зависит от меток; меняется только способ разбиения работы.

## Когда срабатывает AQE

Оценка идёт **до** полной материализации ключей — по статистике ANALYZE (если есть) и кардинальности фильтра / JOIN / подзапроса.

| Запрос | AQE |
|--------|-----|
| Тяжёлый SELECT / широкий JOIN / скан без узкого индекса | Да, если оценка ≥ порога |
| EQ + LIMIT по покрывающему индексу | Нет — локальный индексный путь |
| Несколько шардов и очень большая оценка | `DIST_MAP` — map по **локальным** шардам этого узла, не рассылка SQL на весь кластер |
| Без ANALYZE, малая оценка | Нет — консервативно локально |

`DIST_MAP` не означает «отправить тот же SELECT пирам». При консистентной репликации пиры уже держат копию; разлёт identical-SQL по пирам выключен.

| Оценка кандидатов | Поведение |
|-------------------|-----------|
| меньше **10 000** | Обычно локальный путь без AQE |
| **≥ 10 000** | AQE на узле: параллельный скан кусками |
| **≥ 50 000** и **≥ 2** шарда | Partitioned map по локальным шардам |

Индекс-покрытые остаточные фильтры не считаются тяжёлыми. Без ANALYZE оценка консервативна (только локально). Горячий путь после материализации ключей **не** пересчитывает тяжесть по `keys.size()`.

## Оценка тяжести (порог AQE)

| Часть | Роль |
|-------|------|
| `QueryHeavinessEstimator` | Оценка по данным ANALYZE и кардинальности фильтра / JOIN / subquery |
| `QueryHeaviness` | Пороги выше (10 000 / 50 000) |
| Горячий путь | Без повторной оценки тяжести после материализации ключей |

### Если допуск отказал или кажется «не тем»

| Симптом | Что проверить |
|---------|----------------|
| Нет AQE на большом SELECT | Есть ли ANALYZE; покрывает ли индекс предикат (тогда путь лёгкий) |
| Слишком много параллельных тяжёлых запросов | Лимит одновременных тяжёлых работников (`HeavyQueryAdmission`) |
| Ожидали DIST_MAP, получили только AQE | Число шардов домена и оценка кандидатов |

## AQE на узле

| Класс | Роль |
|-------|------|
| `AdaptiveParallelScan` | Параллельный map-merge по ключам в сериализованных байтах |
| `HeavyQueryAdmission` | Лимит одновременных тяжёлых работников (очередь на logic VT) |
| `AdaptiveChunkScheduler` | Переразбиение / укрупнение незавершённых кусков по ходу выполнения |

Ключи JOIN и фильтра остаются `byte[]` до границы SPI / `SqlResult`.

## Распределённый MapReduce

По умолчанию разрешение ключей **локальное**. При консистентной репликации пиры держат ту же копию, поэтому разлёт identical-SQL по пирам — не MapReduce и выключен.

| Класс | Роль |
|-------|------|
| `ShardPartitionPlanner` | Бакеты ключей по domain shard |
| `DistributedKeyFanOut.mapReduceByShard` | Partitioned map при тяжёлом распределённом плане |

Reduce сливает непересекающиеся куски результата по проводу. Карты `Object` не используются как ключи join/filter.

## SIMD и остаточный фильтр

| Класс | Роль |
|-------|------|
| `WireResidualBatch` | Пакетная проверка остаточного фильтра по blob в кадрах; простой EQ — SIMD-путь |
| `ArrayVectors` | Vector equals / compare; сложные предикаты — скалярный запасной путь |

JVM: `--add-modules=jdk.incubator.vector`. Без модуля загрузка Vector-ядер падает.

## Правила пути запроса

1. Ключи остаются бинарными (`byte[]` / `WireSpan`) — без `toRowMap` → повторного кодирования для пробы индекса.
2. Без долгой синхронизации на VT / Reactor / Netty EL.
3. Разбор SQL — только ANTLR.
